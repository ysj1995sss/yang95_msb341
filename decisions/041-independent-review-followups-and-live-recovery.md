## Choices

- Summary skill listings may reorder supported terms, but a new non-list context cannot turn
  them into tool use at an employer/project. Recognize explicit and clear bare comma listings;
  preserve existing source activities. This is conservative deterministic protection, not a
  universal semantic truth checker. Ambiguous newly added claims require source correction.
- Reuse the shared named-tool vocabulary for Rust/Swift instead of relying on whether the job
  asks for them. A profile-wide mention still does not establish use in a particular activity.
- Preserve unknown explicit lowercase platform objects as Check yourself. Exclude ordinary
  connectors/determiners without losing the named object that follows a determiner. Keep
  generic capability evidence distinct from product experience.
- Streamlit Start/Continue/redo refuses an active one-off upload before launching a batch,
  matching the existing API rule and master-resume policy.
- Complete the existing read-only review instead of creating another seat or altering spending
  limits. The final code-review approval excludes live conversion reliability and human tests.
- Record model no-answer as operationally recovered by the existing Continue path. Its original
  diagnostics were unavailable; no invented root cause or speculative retry/provider change.
- Record the two live Word cleanup locks as an open release risk despite successful final
  retries. A follow-up conversion spec/reproduction should establish document/session ownership;
  neither killing all Word processes nor ignoring cleanup failures is approved by this decision.

tool availability still permits false associations. Dropping every determiner loses products
such as The Trade Desk. A successful retry alone is not a reliability fix or a pristine run.
